# The Ask page, measured against its mock

Measured 2026-09-05 on `feat/ask-page`, against `docs/counter/ask-page-mock.html`,
in a real Chromium: desk at 1440×900, phone at 390×844 (iPhone UA), light and
dark (`counter-theme` in localStorage, the way the fidelity suite sets it). The
dev DB held five threads. Zero console errors on every capture after the
hydration fix in `fix(ask): the server and the browser print the same clock`.

`ask` is reported and not gated by `npm run fidelity` — the manifest says why —
so this is the record. Gate: `npm run tokens` clean · `npx tsc --noEmit
--incremental false` clean · `npm run build` exit 0.

Also matched: the empty state (`empty-light.png` — "Ask about All stores.", six

`gpt-4o-mini-transcribe` → the words land in the field, never sent).

## Deliberate differences

- **Scope chips are statements** (D6). The mock drew them as buttons with a
  swap glyph; here they are labels. The date control in the head and the store
  switcher in the rail are the two places scope changes.
- **Photo attach is not drawn** (D7, sub-project 4).
- **Fork from here on a live turn is not offered**: the SDK's client ids are
  not `Message.id`. It appears on the same turn after the refresh that lists
  it, and "Fork from the end" is always in the rail.

## Interaction scripts, run in the real page

- (a) send → Esc → Continue: the stopped block appears with the elapsed time;
  Continue re-sends the question as a follow-up. ✓
- (b) ⋯ → Rename → Enter: the row and the head update after `router.refresh()`.
  ⋯ → Delete → Keep: the row returns. ⋯ → Delete → Delete: the row slides out
  180ms and the list re-reads; deleting the open thread returns to the empty
  Ask. ✓
- (c) `/` → ↓ → Enter → send: `/spend`'s template fills the field and sends. ✓

## What the next pass should look at

- `rateAskTurn` on a fresh live turn depends on the pre-minted `chatTurnId`
