# PM Audit P0+P1 Execution Plan — 2026-07-27

Source: full-app product/design audit (three independent assessments + automated detector). User approved scope: P0 breakage first, then P1 bloat/drift. Mobile direction decided: **lean glance-and-do tool** (home glance, stock count, invoice approval, orders; deep analysis hands off to desktop).

## Global Constraints

- **Editorial design system only** on `/dashboard/*`: tokens `--ink`, `--ink-muted`, `--ink-faint`, `--paper`, `--hairline`, `--hairline-bold`, `--accent`; `.inv-panel` for sections; `.inv-row`/`.order-row` for interactive rows; `.toolbar-btn` for toolbar/segmented controls (active = `--accent` border + text + `--accent-bg` ground). NO generic Tailwind palette classes (`bg-sky-*`, `text-red-500`, etc.), no shadcn `<Card>`, no `shadow-*`, no `rounded-xl`. The system of record is `DESIGN.md` at repo root (NOT `docs/frontend-patterns.md`, which no longer exists).
- **Two-tier typography**: numbers in DM Sans 500–600 with `font-variant-numeric: tabular-nums lining-nums`; Fraunces italic for prose/display only; JetBrains Mono only for captions/folios/SKUs/labels.
- **Mobile** (`src/app/(mobile)/**`) uses the same token file (`@/styles/editorial-tokens.css`) + `editorial-mobile.css` conventions. Match existing mobile component idioms (`MToolbar`, masthead figures, `SectionList`, `m-readonly-note`).
- **Before deleting or moving any file**, verify importers with grep across `src/**`, explicitly including `src/app/(mobile)/**` and `src/lib/mobile/**` (the mobile-import check from `docs/refactor-playbook.md`).
- Re-export shims (if any needed) must NOT contain `"use server"`.
- **Verification per task**: `npx tsc --noEmit` must pass; run any existing tests covering touched code (`npm test -- <pattern>` — vitest; e2e specs are excluded, they need a dev server). Report commands + output.
- **Commits**: conventional-commit style messages. Do NOT add any `Co-Authored-By` line.
- Do not touch `prisma/schema.prisma` (the MANAGER role is an open product decision, out of scope).
- Preserve existing behavior for DEVELOPER-only surfaces (`/m/monitoring`, `/dashboard/admin/monitoring`).

## Task 2 — Menu Profit: honest failures + typography/toolbar compliance

Files: `src/app/dashboard/menu-profit/` — `sections/kpi-strip-section.tsx`, `sections/profit-matrix-section.tsx`, `sections/item-table-section.tsx`, `sections/coverage-section.tsx`, `components/menu-profit-shell.tsx`, `components/menu-profit-table.tsx`.

Problems (from design review):
- All four sections do `if (!result?.ok) return null` — a data error renders a blank page and the surrounding `SectionErrorBoundary` never fires.
- `item-table-section.tsx` returns `null` for `rows.length === 0` while `profit-matrix-section.tsx` renders a proper empty panel — inconsistent.
- `menu-profit-table.tsx:62` sets `font-mono text-xs` on the whole `<table>`, so every number renders in JetBrains Mono — Two-Tier Rule breach. Numbers must be DM Sans 500–600 tabular.
- `menu-profit-shell.tsx:39-43` hand-rolls a lookback toolbar with active state `border-[var(--ink)] bg-[var(--ink)] text-[var(--paper)]` (inverted ink). Must use the existing `.toolbar-btn` idiom (see `src/app/dashboard/orders/components/orders-content.tsx` for the reference usage; active = `.toolbar-btn` + active class → `--accent` border/text + `--accent-bg`).
- `menu-profit-table.tsx:89-91` uses `font-display italic` without `font-variation-settings` (Optical-Size Rule). Follow how other pages set Fraunces (grep `font-variation-settings` or use an existing class like the docket title classes in `editorial-dashboard.css`).
- `kpi-strip-section.tsx:34` computes an unused `muted:` value — delete it.

Do:
1. Replace every `return null` on `{ok:false}` with a rendered `.inv-panel` failure state in editorial prose (match `/dashboard/decisions` empty-state voice: e.g. "We couldn't load this section right now. Try refreshing in a moment."). Keep `return null`-on-error OUT; empty-data states get honest copy too (item table matching the matrix section's empty-state pattern).
2. Fix the table typography: table stays default body font; numeric cells get DM Sans 600 with tabular figures (there is almost certainly an existing class or the `.inv-row` total pattern — reuse, don't invent). Mono is allowed only on SKU/label-class cells.
3. Replace the hand-rolled toolbar with `.toolbar-btn` buttons.
4. Fix the Fraunces usage to carry proper `font-variation-settings`.

Verify: `npx tsc --noEmit`; run any menu-profit/menu-engineering tests (`npm test -- menu` or similar — discover with `ls src/**/*menu*test*` / vitest config).
